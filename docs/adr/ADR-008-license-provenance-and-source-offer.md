# ADR-008：发布包保留许可证、溯源记录与对应源码获取方式

## 状态

规划阶段已接受。

## 决策

每个 FPK 发布产物必须附带机器可读和用户可读的软件物料与许可证清单，并记录所有
随包分发资产的固定来源修订、校验和、构建方式、目标架构和构建时间。包含 GPL-3.0
Aria2 Pro Core 二进制的发行，必须在发布时同时提供与该二进制对应的完整源代码获取
方式和 GPL 许可证文本；不得只指向会变化的上游默认分支或“最新版本”。

## 原因

离线基线表明 Aria2 Pro Core 的许可证为 GPL-3.0，而 AriaNg、P3TERX Docker 和
`aria2.conf` 脚本为 MIT。二进制、静态资源、配置模板和管理器的许可证义务不同；
仅在 README 中笼统标注上游名称，无法证明某一 FPK 中实际分发了什么，也无法确保
GPL 对应源码与构建产物匹配。

## 影响

- Phase 3 为每个架构建立不可变的产物清单，至少含文件名、SHA-256、来源、revision、
  许可证、构建命令或构建环境标识。
- FPK 中保留第三方许可证和版权声明；发布页或同版发布附件提供 GPL Core 对应源码包
  或稳定的、版本固定的源码获取地址。
- 若修改 GPL Core 或将其与其他代码形成需要一并提供对应源码的组合，发布前必须进行
  许可证合规复核并更新来源清单。
- P3TERX Docker 和配置仓库即使仅被参考而不随包分发，也要在设计/构建记录中区分
  “行为参考”与“已分发资产”，避免错误声明。

## 验收

每个待发布 FPK 必须能从其版本号和架构反查到：Core 二进制哈希、对应源码修订或源码
包哈希、构建记录、第三方许可证清单和用户可访问的源码获取方式。任一项缺失时，
该产物不得进入 Phase 7 发布验证。
