# ADR-019：安装向导与应用设置统一收口六个运行参数

## 状态

已接受，2026-11-24 起生效，对应发布版本 `0.2.4`，尚未在设备验收。

## 背景

ADR-006 已声明「端口通过安装向导和应用设置修改」，但落地时只做到一半：

- `wizard/install` 只有 RPC 端口与 BT 监听端口两项；
- `wizard/config`（应用中心「应用设置」）完全不存在，`cmd/config_init` 与
  `cmd/config_callback` 是空壳脚本，直接 `exit 0`；
- DHT 监听端口、RPC 密钥、归档模式（`SPECIAL_MODE`）、下载文件夹路径只能在
  `config.json` 里手工改，普通用户没有入口；
- RPC 密钥由安装脚本随机生成 48 位后即固定，用户无法更换。

用户要求这六项在安装时能设置，安装完成后也能在应用设置里修改，并且重启后生效。

## 决策

1. **六个字段统一走飞牛向导机制。** 字段名固定为 `wizard_rpc_port`、
   `wizard_listen_port`、`wizard_dht_listen_port`、`wizard_rpc_secret`、
   `wizard_special_mode`、`wizard_download_root`。`wizard/install` 与
   `wizard/config` 共用同一字段名：向导值以环境变量注入生命周期脚本，改名会让
   已发布版本的用户输入失效。

2. **落盘逻辑收口到 `aria2-manager --apply-wizard`。** 端口校验、端口互斥、密钥
   字符集、下载目录是否位于飞牛共享目录、归档目录派生与属主继承，全部复用常规
   配置路径的同一份代码。生命周期脚本只做三件事：`*_init` 预先校验（安装阶段
   二进制尚未落地，无法调用管理器），`*_callback` 调用管理器落盘，`config_callback`
   在服务运行时执行一次受控重启。

3. **空值语义是“不修改”。** `wizard/config` 中端口、密钥、下载目录的 `initValue`
   为空，归档模式提供「保持当前设置」选项。这样无论飞牛是否回填上次提交值，保存
   设置都不会把用户没有触碰的字段重置为出厂值；安装流程的空值则回落到出厂默认，
   密钥为空时自动生成随机值，保证新装不需要用户理解 RPC 密钥也能用。

4. **RPC 密钥下限由 32 位放宽到 16 位，并限制字符集。**
   允许 `[A-Za-z0-9._-]`：`aria2.conf` 由 shell 逐行写出，含空白、引号、反斜杠或
   `#` 的取值会截断行或注入额外选项，因此在入口处拒绝。密钥先校验后落盘，避免
   留下「配置已改、重启后连不上」的中间态。

5. **下载目录允许尚不存在，但只能在已授权根内创建。** 逐级创建新建目录并把属主
   跟随上级目录，避免以 root 身份建出应用用户无法穿越的中间目录。归档目录仍按
   ADR-018 恒定为 `<下载目录>/completed`，不新增配置项。

## 后果

- 六个参数在安装期与运行期各有一个入口，任何一个入口的校验规则必须与
  `aria2-manager --apply-wizard` 保持一致；`*_init` 里的 shell 校验是同一口径的
  提前反馈，不是第二套规则。
- `config_callback` 会在服务运行时重启一次应用（约 8 秒），端口、密钥、下载目录
  只有重启后才生效；应用未运行时跳过重启，配置在下次启动时读取。
- `aria2-manager --apply-wizard` 在配置与密钥都没有变化时以退出码 `2` 结束，
  `config_callback` 据此跳过重启：用户在设置页原样保存一次不应打断正在进行的下载。
- 启动期 `--ensure-ports` 仍会在端口被占用时自动改端口并回写配置。用户手填的端口
  不是硬约束，而是首选值。
- 该机制依赖飞牛 `GET/POST /v1/config/wizard` 把 `wizard/config` 渲染到应用设置页。
  离线参考资料未记录该接口的字段回填行为，因此空值语义按“最坏情况”（不回填）设计。
