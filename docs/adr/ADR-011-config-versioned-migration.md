# ADR-011：配置版本号与显式迁移

## 状态

已接受，2026-09-04 起生效，对应发布版本 `0.1.91`。

## 背景

`ADR-010` 之后，`config.json` 的默认值集合仍在演进：下载目录从安装包私有目录改为
飞牛数据共享目录、归档目录改为下载目录下的 `completed`、`dht_message_timeout` 早期
被写成带单位的 `10s`（Aria2 只接受纯秒数）。这类历史取值有两个特点：

1. 它们只可能是机器写出来的，用户在下拉里选不到，因此可以安全替换；
2. 一旦落到磁盘，常规读取路径会直接判定非法，`aria2-manager` 在 `log.Fatal` 后退出，
   表现为升级后应用无法启动。用户只能卸载并清空配置，等于用回退换可用。

同时，`fpk/cmd/main` 在每次启动时执行 `--ensure-ports`，把 `json.MarshalIndent` 的结果
同时写回 `/run` 与 `TRIM_PKGETC/config.json`。这意味着**任何不在 Go `config` 结构体里的
键都会在启动时被静默抹掉**。因此迁移不能靠"多写一个键"来表达状态，必须使用结构体里
真实存在的字段。

## 决策

1. 引入 `config_version` 整型字段，值来自常量 `configVersion`（当前为 `1`）。它是
   `config` 结构体的成员，因此能够活过启动期的重写；`install_callback` 在生成新配置时
   直接写入该键。
2. 迁移只在显式模式下发生。管理器新增 `--migrate-config`：读取
   `TRIM_PKGETC/config.json`，执行 `migrateLegacyConfig`，原子重写文件后退出，并把中文
   变更说明打印到标准输出供生命周期日志记录。常规读取入口（环境变量、标准输入、文件
   描述符、文件）统一走 `decodeConfig`，**不做任何改写**，保持 `ADR-010` 第 7 条"不
   悄悄改写旧配置"的承诺。
3. `install_callback` 与 `upgrade_callback` 在检测到配置已存在时调用 `--migrate-config`，
   失败用 `|| true` 兜底，绝不阻断安装或升级。调用点在二进制 `chmod 755` 之后，否则刚
   解包的产物不可执行。
4. 迁移只处理"机器写出的值"：`"10s"` 修正为 `"10"`；等于 `TRIM_PKGVAR/downloads` 的
   历史下载目录替换为共享目录首项；仍位于历史下载目录下的 `completed` 归档目录跟随到
   新下载目录。缺失的键由 `normalizeConfig` 补齐默认值并被记入变更说明。用户显式选择的
   下载目录、自定义归档目录名、以及 `special_mode=off` 一律保持原样。
5. 迁移必须幂等。`migrateConfigFile` 在重写前比较归一化后的 JSON 与磁盘内容，一致时
   返回空变更列表，因此第二次执行完全静默，升级日志不会反复刷出假变更。
6. 生命周期脚本里统一使用 `if [ -x ... ]; then` 形式判断可执行性。`[ -x ... ] && var=...`
   在条件为假时返回非零，会让 `set -e` 的脚本静默中止，这正是历史上"回调没跑完"的来源。

## 后果

- 升级可以修复历史坏配置，用户不再因为一个非法取值而必须清空全部设置。
- 迁移不覆盖用户意愿，因此可以放心地在每次安装与升级时执行。
- 新增配置项时必须同步加入 `config` 结构体，否则会在启动时被抹掉；这是启动期重写策略
  带来的长期约束，`ADR-011` 的记录就是提醒后续开发者。
- 常规读取仍然严格校验：非法配置在迁移之外的路径上照旧报错，避免"带着坏值继续跑"。
