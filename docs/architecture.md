# 架构设计

## 组件

### FPK 外壳

FPK 外壳包含 manifest、资源和权限声明、生命周期脚本、配置向导、图标及应用运行文件；它是 App Center 唯一安装和管理的单元。

### Aria2 Pro Core

`aria2c` 是架构相关的原生二进制。它读取生成且校验过的配置，只在回环地址监听可配置的 JSON-RPC 端口，负责下载协议、会话持久化、DHT 状态和下载事件回调。RPC 默认端口为 `6800`，BT/DHT 默认端口为 `6888`；两者都可独立修改。

### 管理器与统一网关服务

管理器为小型静态 Go 二进制，监听 `$TRIM_APPDEST` 中与 `gatewaySocket` 一致的 Unix Socket，并负责：

- 提供固定版本 AriaNg 静态资源和飞牛 UI 适配层；
- 校验网关提供的管理员身份；
- 代理本机 aria2 HTTP JSON-RPC；
- 在服务端加入 RPC token；
- 拒绝任意后端地址和不支持的 RPC 传输路径；
- 为生命周期脚本提供 PID 与状态信息；
- 经本地 RPC 按计划刷新 Tracker。

### UI 适配层

适配层保持极小范围：使用 `@trimjs/web-app` 请求飞牛目录、获取授权、打开文件管理器、打开应用设置、响应主题和语言变化；不重复实现 AriaNg 的任务管理能力。

## 数据边界

| 位置 | 内容 | 保留策略 |
| --- | --- | --- |
| `$TRIM_APPDEST` | 不可变的打包二进制和 UI 资源 | 升级时替换 |
| `$TRIM_PKGETC` | 用户配置、生成的密钥、配置档 | 保留 |
| `$TRIM_PKGVAR` | aria2 会话、DHT 数据、日志、PID | 保留 |
| 共享目录或授权路径 | 下载和归档的用户数据 | 除非用户明确选择，卸载时不删除 |

## 网络边界

- 浏览器到飞牛：通过 `/app/aria2` 的已认证 HTTP(S) 会话。
- 飞牛网关到管理器：仅 Unix Socket。
- 管理器到 aria2：仅回环 HTTP JSON-RPC，目标端口来自已校验的配置。
- Aria2 对等连接：NAS 主机上的可配置 TCP/UDP BT/DHT 监听端口；路由器和防火墙转发由 NAS 管理员负责。

## 端口配置流程

安装向导和应用设置提供两个独立字段：`rpc_port`（默认 `6800`）和
`listen_port`（默认 `6888`）。管理器在保存前校验端口范围、占用情况及两者
是否冲突；变更后先暂停或提醒用户处理活动任务，再由生命周期脚本受控重启
Aria2，并检查新端口确实监听。启动失败时保留旧配置并报告原因。

## 架构决策

- `ADR-001`：使用原生 FPK，不使用 Docker 运行时。
- `ADR-002`：使用统一网关和 Unix Socket，不开放 RPC 端口。
- `ADR-003`：使用静态 Go 管理器，不使用 CGI 或 Node.js 服务。
- `ADR-004`：第一版为单个管理员管理的 Aria2 实例。
- `ADR-005`：固定离线资产，禁止运行时下载可执行内容。
- `ADR-006`：RPC 与 BT/DHT 端口可独立配置。
- `ADR-007`：以网关、专属用户和授权目录作为安全边界。
- `ADR-008`：发布包保留许可证、溯源记录与对应源码获取方式。
